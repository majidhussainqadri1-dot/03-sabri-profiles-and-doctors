Real File26 Search serializes persisted \`entity_type\` into public result facets and doctor-tier logic after calling File03 \`can_view\`. Original File03 \`can_view\` compared the native profile version and verified-doctor boolean but not the persisted \`entity_type\` against canonical \`profile_type\`. A historical or corrupted Founder index row with \`entity_type=doctor\`, \`verified_doctor=false\`, and matching owner version could pass and be labeled a doctor.

- **Fail-first isolated PHP reproducer:** canonical \`Founder\`, indexed \`doctor\`, old \`can_view=true\`, process exited 2.
- Added \`tests/file26-founder-badge-separation-runtime.php\` negative Founder-as-doctor and invalid entity-type cases.
- Aligned current version and doctor-revocation test fixtures with the actual File26 \`entity_type\` column.
- Source candidate correction: require \`entity_type\` exactly \`founder\`, \`doctor\`, or \`member_profile\` according to the *current* trusted owner profile type, and fail closed for unknown types.
- **Corrected isolated PHP reproducer:** Founder-versus-doctor \`can_view=false\`, process exited 0.
